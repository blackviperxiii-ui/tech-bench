# Tech Bench v1.2.26: Rearch stage 7, shell page registry

## Problem
The shell's four pages lived in three parallel places: the panel array and its `shellPage0..3` names in `ShellForm`, the switch-bar title array, and `AdapterPrefs.ShellPageCount = 4` for the saved-page clamp. Callers jumped to Search with a bare `ShowPage(0)`. Adding or reordering a page meant editing all of them in step, and a mismatch would silently restore the wrong saved page.

## Change
- New `src/Core/Shell/ShellPages.cs`: `ShellPageId` (persisted ints, never renumbered), `ShellPageInfo` (id, title, panel name) and the `ShellPages` registry (`Count`, `At`, `Titles`, `Clamp`).
- `ShellForm` builds its page panels and switch bar from the registry and jumps with `ShowPage(ShellPageId.Search)`. Startup restore keeps `ShowPage(0, false)` / `ShowPage(shell, false)` unchanged.
- `AdapterPrefs.ShellPageCount` and `ClampShell` read the registry.
- New SelfTest case `shell page registry` (Order 95) pins titles, panel names, saved ints, clamping, a saved-prefs restore, and that `ShellForm` and `tools/LayoutAudit.cs` agree with the registry. `ExpectedCaseCount` 43 -> 44. Lockstep version bump.

## Behaviour
Unchanged: same four pages, same order, titles, panel names and saved-page values.

## Non-goals
- No change to INLINE 7, Safety files, updater, page bodies or layout.
- Page bodies are not yet built by the registry; that is a later stage.
