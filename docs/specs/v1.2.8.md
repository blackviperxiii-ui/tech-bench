# Tech Bench v1.2.8: Release-path cleanup (private, manual Setup)

Stacked on PR #19 (v1.2.6), then PR #20 (v1.2.7). Branch `cursor/v1-2-8-release-path` starts at #20's head `c428c95`. This PR merges only after both.
Backlog items: C2 (operator doc / release script), C3 (shop rollout one-pager), C4 (first-install smoke gate), C5 (version lockstep), C6 (single source list). Source: `/workspace/tech-bench-backlog.md`.

## Decisions (settled; not reopened here)
- The update path stays manual Setup for now.
- `Updater.DefaultManifestUrl` and the updater's behavior do not change.
- The password DB and the README password line are not touched.
- `http://` and `file:` stay allowed.

## Acceptance criteria
- **AC1:** Remove the dead "Publish updater files to public dist repo" CI step and `tools/publish-dist.ps1`. Also remove the dist-upload instructions from `release.bat` and README. Release output tells people to attach the Setup exe, `TechBench.exe` and `latest.json` to the **private** GitHub release, and to install with the shop Setup. Nothing may reference creating or uploading to a public dist repo. Every build and test step stays. Self-tests that asserted the old publish path are inverted to assert that it is gone. This is an approved behavior change, not a weakening.
- **AC2:** The version is 1.2.8 everywhere #20 bumped it (`AppVersion.cs`, the SelfTest stamp, `app.manifest` `1.2.8.0`) and in the README "Current stamp" line, plus any other README version text.
- **AC3:** Add `docs/shop-rollout.md`, a plain-English manual Setup guide for shop PCs. It covers where to get Setup, install and upgrade, confirming the version in Help → About, rollback to the previous Setup, and where the data lives so upgrades keep it. It is based only on what the code and `installer/techbench.iss` actually do.
- **AC4:** One source-file list. Response files under `sources/` are the source of truth, and `build.bat` and both `test.bat` compiles (SelfTest, LayoutAudit) read them. A self-test fails if the scripts or lists drift: a root `.cs` file that is unlisted or listed twice, a listed file that is missing, or an inline `.cs` list coming back in a script.
- **AC5:** A first-install smoke gate in CI, after the Setup exe is built:
  - silently install it per-user into a temp dir;
  - run the installed exe with a new `--smoke` switch that exits 0 without UI when the version is 1.2.8 and the bundled KB loads;
  - confirm the installed file/product version is 1.2.8;
  - uninstall silently and confirm the exe is gone.
  CI fails if any step fails.
- **AC6:** All existing tests stay, and CI is green on the PR head.

## Non-goals
Updater logic or URL, the password DB, code signing, UX, IntelliDealer.
