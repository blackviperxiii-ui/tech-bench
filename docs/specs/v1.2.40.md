# Tech Bench v1.2.40: fixes from the PR #69 review

## Problem
A review of the beta-to-main promotion (PR #69, `2902f04`) found ten issues; a QA walkthrough on 2026-10-21 re-verified them. Four (the 429 retry sleep, `GatewayConfigured` dropping OAuth-only, 301/302 POST-to-GET, and the narrowed `Ok`) are in IntelliDealer code that v1.2.31 (#78) already removed from beta, so they leave `main` at the next promotion. Draft PR #85 (v1.2.38) fixed four more but was based on v1.2.37 and conflicted with v1.2.39; it also left two findings open:

1. `SafeOpen.HasExecutableAssociation` read `S_FALSE` (1) from the `AssocQueryString` size query as "no association". With a null output buffer the API returns `S_FALSE` and the length, so every KB document and work-order photo was refused with "No program is associated". (#85)
2. `KbIndex.SpnHits` dropped any match with score 0, so a NOTE or FILE that names the SPN only in its body no longer showed on the INLINE 7 tab. (#85)
3. `Program.Crash` showed the dialog on whatever thread raised the exception; on an MTA background thread the dialog and Copy details fail. (#85)
4. `ShellForm` restored the saved shell page only when the saved RP1210 adapter was installed, so an office PC always opened on Search. (#85)
5. `SettingsStore.SaveJobCustomer` rewrote `settings.json` on every Model or Serial keystroke even when the customer had not changed. (#85)
6. `ShellForm.ShowPage` and the INLINE 7 inner-page switch pass `CurrentAdapterId()` to `AdapterPrefs.Merge`; with no adapter installed that is `""`, which overwrote the saved id, so the inner page never restored once the adapter was back. (new here)
7. `WorkOrderControl.Reload` set `_jobWoRestoreDone` when it tried the saved `LastWo`; if that work order was gone, nothing was selected and no later Refresh ever auto-selected a row. (new here)

## Change
- Carries the three #85 commits forward onto the v1.2.39 tip (conflicts in `Program.Crash`, `SelfTest.Crash` and the four version spots resolved by keeping both sides).
- `AdapterPrefs.Merge`: a null or empty adapter id leaves the saved id alone; shell and inner page still merge.
- `WorkOrderStore.PickAfterReload`: pure selection rule (`Keep`, `First`, `None`). `Reload` uses it; a saved work order that is gone now selects the first row like a launch with nothing saved. Current-WO-vanished and after-Clear-job still select nothing.
- Lockstep version bump (4 spots) to v1.2.40.

## Tests
- From #85: `KB load resilience` SPN body-only hits; `crash log (TB1d)` RunOnSta from MTA; `data safety` `.txt` association on Windows CI; `persist startup (no wipe)` same-customer no rewrite.
- `adapter discovery`: `Merge("", 1, 2)` keeps the saved id `OTHER` and still merges pages 1 and 2.
- `WorkOrder key, tag, list label, clock line`: seven literal `PickAfterReload` outcomes, including saved-WO-gone → `First` and after-Clear-job → `None`.
- No new SelfTest case, so `ExpectedCaseCount` stays 53.

## Non-goals
- No IntelliDealer change (removed on beta). No J1939, updater, `.github/` or UI layout change.
- No merge to `main`; this lands on `beta` and reaches `main` at the next promotion.
