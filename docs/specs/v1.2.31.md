# Tech Bench v1.2.31: Remove the dealer DMS integration

## Problem
user asked to clear out everything to do with the dealer DMS (Azure API Gateway) integration. The work-order page carried Sign off, From ID, media post-back and a gateway-backed Log on / Log off. `IdSettings` mixed gateway secrets with the shop settings that work orders and shop sync still need (tech name, share folder, assigned-WO file).

## Change
- New `src/Core/Settings/ShopSettings.cs` (core) holds `TechId`, `ShareFolder`, `AssignedFile` and the folder, exe-dir, sibling-share and sanitize helpers. It is stored in `%LOCALAPPDATA%\TechBench\shop-settings.json`; a beside-exe `shop-settings.json` fills blanks.
- One-time migration: when `shop-settings.json` is missing, `Load` copies only `TechId`, `ShareFolder` and `AssignedFile` out of the old `id-settings.json` (LocalAppData, plus beside-exe to fill blanks). Every other key in that file is ignored, nothing is decrypted, and the old file is never written, moved or deleted.
- New `src/Shell/ShopSettingsForm.cs`: Shop → Shop settings… (tech name, share folder, assigned WO file). The work-order Settings button opens it too.
- Deleted `src/Safety/IdGateway.cs`, `src/Safety/IdSettings.cs`, `src/Shell/IdSettingsForm.cs`.
- `WorkOrderControl`: no Sign off or From ID buttons, no media post-back. Log on / Log off write a `shop-logon` / `shop-logoff` clock event only.
- `WorkOrder`: removed `ApiSignOff`, `ApiLogOn`, `ApiMessage` and the clock's posted flag. Old packets that carry those keys still load (the serializer drops unknown keys) and their clock events render as history.
- `WorkOrderStore` and `ShopSync` take `ShopSettings`.
- Tests: deleted `tests/SelfTest.Gateway.cs` (case `IdGateway POST 307 redirect refused` plus DPAPI, token and ServiceToday checks), the gateway half of `work orders / shop share`, the subscription-key mask check and the sign-off label checks, with user's OK. The work-order merge and backup-recovery checks moved to `tests/SelfTest.Job.cs`. New cases `shop settings migration` (Order 261) and `legacy work-order packet loads` (Order 262). `ExpectedCaseCount` 46 -> 47.
- Docs: README, cheat sheet, shop rollout, house rules wording and historical specs no longer name the integration.

## Behaviour
Work orders, share with shop, photos, reports and shop sync behave as before. The app makes no outbound HTTP for work orders. A user's existing `id-settings.json` stays on disk untouched.

## Non-goals
- Deleting users' old settings files or stored credentials.
- Updater, installer, INLINE 7, password DB, `.github/`.
