# Tech Bench v1.2.41: scrub a real home-folder path from the shipped KB

## Problem
The field database that ships with the app (`kb/data/*.json`) recorded each manual's source path as an absolute path under a real Windows profile folder (`C:\Users\<name>\Documents\...` and `...\OneDrive\...`, with `\\` in JSON and `/` in some fields). That puts a person's account name in a public repo and in every install. `pii-guard` did not catch it: its home-path check only matched `/home/name` and `/Users/name` with forward slashes, and the folder name was not in its hash list. One `UiLayout.cs` comment had the same path.

## Change
- Replace that profile folder name with `user` in `usb-manuals.json`, `INDEX.json`, `kb.json`, `rental-equipment-info.json`, `rental-portable-filters-oil.json` and the `UiLayout.cs` comment. Only the path text changes; every file still parses as JSON and record counts are unchanged.
- `pii-guard`: the home-path pattern also matches backslashes (single and the doubled JSON form) and is case-insensitive, and the folder name is added to the hash list as an `H` entry (stored only as a SHA-256 hash).
- Lockstep version bump (4 spots) to v1.2.41.

## Not changed
- `kb/data/passwords/ifix-passwords.json` carries the same path, but the password DB is an open owner decision and is left untouched. With the stronger guard it now fails `pii-guard` until the owner decides.

## Tests
- No SelfTest case changes. `pii-guard` on unscrubbed beta: the old script prints `clean`; the new one flags 4,753 lines across the seven files above (414 of them in the password DB).

## Non-goals
- No history rewrite. The old path stays in git history; that is the maintainer's call.
- Manual source paths were only valid on one PC; this does not try to make them resolve anywhere.
- No J1939, updater, `.github/` or UI change.
