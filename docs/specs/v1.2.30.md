# Tech Bench v1.2.30: Rearch stage 9, shop folder watcher out of the shell

## Problem
`ShellForm` owned the shop-sync folder watching: which folders to watch, the `FileSystemWatcher` list, the 900 ms debounce timer and their teardown, spread over three methods and two fields. The folder choice (shop, notes, files, plus a separate sync folder only when it exists and is not the shared tree) had no test.

## Change
- `src/Features/Sync/ShopWatch.cs` (core): pure `ShopWatch.Dirs(kbRoot, settings)` returns the folders to watch, in the old order.
- `src/Features/Sync/ShopWatcher.cs` (app): owns the watchers and the 900 ms debounce, marshals change pings to the UI thread, and has `Start`, `Restart` and `Dispose`.
- `ShellForm` creates one `ShopWatcher` that calls `RunSync(false)` once changes settle. It replaces `StartWatchers`, `RestartWatchers`, `WatchDir`, `OnShopChanged` and the timer and watcher fields.
- New SelfTest case `shop watch folders` (Order 251, `tests/SelfTest.Sync.cs`). `ExpectedCaseCount` 45 -> 46. Lockstep version bump.

## Behaviour
Unchanged: same folders, same events, same 900 ms settle before a sync, same teardown on close. `ShopSync` (Safety) is called, not changed.

## Non-goals
- `RunSync`, `ApplySyncStatus`, `ShopSync` logic, updater, INLINE 7.
