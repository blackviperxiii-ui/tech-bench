## Fixed decisions (not reopened)
- `Updater.DefaultManifestUrl` is unchanged.
- `http://` and `file:` manifest/download URLs stay allowed.
- No signing, no token, and the password DB is untouched.
- The update path is still manual Setup. The updater code stays, and `update-url.txt` / settings overrides still work.

## Numbers
- **Manifest cap: 64 KiB (65,536 bytes).** Today's `latest.json` is about 214 bytes (version, sha256, url, optional notes). 64 KiB is more than 300× that and leaves room for long release notes. Anything larger isn't a manifest.
- **Payload cap: 32 MiB (33,554,432 bytes).** Today `TechBench.exe` is about 3.2 MB (3,247,104 bytes at v1.2.5, including the embedded field KB) and the Setup exe is about 3.0 MB. 32 MiB is about 10× headroom for KB growth. It still stops a runaway or hostile response well before it fills a shop laptop's disk or memory.
- Redirects: at most 5 hops.

## Acceptance criteria
- **AC1 (size caps):**
  - The manifest and payload downloads each enforce their cap while streaming. They abort when the byte count goes past the cap, whether or not `Content-Length` was sent. A declared `Content-Length` over the cap is refused before the body is read.
  - The payload streams to `TechBench.exe.new.part` in the install folder. On any failure (cap, network, hash) the `.part` file is deleted and nothing is staged. Only a complete, hash-verified payload becomes `TechBench.exe.new` plus its `.sha256` sidecar.
  - The user sees a failure. It never reads as "is current"/"up to date", and nothing is ever half-applied.
- **AC2 (redirects and payload origin):**
  - HTTP(S) redirects are followed by hand (`AllowAutoRedirect = false`), up to 5 hops.
  - A hop to another host or another port is refused. A hop from https to http is refused. Same-host hops are followed, including an http → https upgrade on the same host with default ports (not a downgrade, and not leaving the host).
  - For an http(s) manifest, the payload URL must be on the manifest's host (case-insensitive) and port. The one allowed scheme change is http → https on the same host with default ports. https → http is refused, and so is a `file:` payload.
  - A `file:` manifest (on local disk or a share the shop controls; it can't be redirected) may name a `file:` or http(s) payload, as today. The payload download itself is still capped and hash-checked, and its HTTP redirects are pinned to the payload's own host.
  - Why this rule: today's `release.bat` writes `latest.json` with the payload on the manifest's host (`https://github.com/.../tech-bench-dist/releases/download/vX/TechBench.exe`, while the manifest is `https://github.com/.../releases/latest/download/latest.json`). A shop override feed (`update-url.txt`) is either a share or a plain web server holding both files. Existing file-feed tests (including the one where a `file:` manifest names an `http://127.0.0.1/` payload) and override tests keep passing unchanged.
  - Known consequence: GitHub release downloads redirect from `github.com` to a separate asset host (`*.githubusercontent.com`). If the built-in GitHub feed were ever published again, the updater would refuse that redirect. Whether to allow those asset hosts is a separate owner decision, not part of this PR. The built-in feed is not published today (manual Setup).
- **AC3 (checksum):** `latest.json` already requires `sha256` (or `hash`), 64 hex characters. The streamed payload is hashed and refused on mismatch before anything is staged, and the partial file is removed. No new manifest fields.
- **AC4 (failure path):** Cap and redirect/origin failures use #19's private-build failure wording ("Update feed unavailable … This build is private. Use the shop Setup … never uses a GitHub token."), with the specific reason appended. The silent background check stays silent on failure, and install is still refused while an INLINE 7 session is live. Nothing applies mid-session.
- **AC5 (self-tests):** Using SelfTest's local `HttpListener` feed pattern, cover:
  - an oversize manifest, both with and without `Content-Length`;
  - an oversize payload, both with and without `Content-Length`, including cleanup of the `.part` file;
  - a cross-host or cross-port redirect refused;
  - more than 5 redirects refused;
  - a same-host redirect followed;
  - an https → http downgrade refused (origin-rule unit test, since there is no local TLS);
  - payload origin allowed and refused cases;
  - a hash mismatch refused with cleanup.
- **AC6:** 1.2.9 everywhere #21 bumped it: `AppVersion.cs`, the SelfTest stamp, `app.manifest` `1.2.9.0` and the README stamp. The CI smoke gate passes at 1.2.9. All existing tests stay, and CI is green on the head.
