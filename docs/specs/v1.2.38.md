# Tech Bench v1.2.38: fixes from the PR #69 review

## Problem
A review of the beta-to-main promotion (PR #69, `2902f04`) found ten issues. Four (the 429 retry sleep, `GatewayConfigured` dropping OAuth-only, 301/302 POST-to-GET, and the narrowed `Ok`) are in IntelliDealer code that v1.2.31 (#78) already removed from beta, so they leave `main` at the next promotion. The other six still apply on beta:

1. `SafeOpen.HasExecutableAssociation` read `S_FALSE` (1) from the `AssocQueryString` size query as "no association". With a null output buffer the API returns `S_FALSE` and the length, so every KB document and work-order photo was refused with "No program is associated".
2. `KbIndex.SpnHits` dropped any match with score 0, so a NOTE or FILE that names the SPN only in its body no longer showed on the INLINE 7 tab.
3. `SpnHits` carried its own copy of the Search match, score and sort loop (finding 3 came from that copy drifting).
4. `Program.Crash` showed the dialog on whatever thread raised the exception. On a background thread with no active form that was MTA, where the dialog and Copy details fail. Closing the dialog with X also left a UI-thread fault running though the text says the app needs to close.
5. `ShellForm` restored the saved shell page only when the saved RP1210 adapter was installed, so an office PC always opened on Search.
6. `SettingsStore.SaveJobCustomer` rewrote `settings.json` (temp, replace, `.bak`) on every Model or Serial keystroke even when the customer had not changed.

## Change
- `SafeOpen`: treat 0 and 1 from the size query as success when it returns a length, and pass `ASSOCF_INIT_IGNOREUNKNOWN` so an unregistered extension fails instead of answering with the "Open with" picker (Windows CI showed it answers S_FALSE plus a length for those).
- `KbIndex`: Search's token match and score move into `Matches`, its sort into `Rank`. `SpnHits` runs its three queries (`spn N`, `N`, the SPN name) through `Matches`, keeps one row per entry at its best score (score 0 included) and ranks once.
- `CrashForm.RunOnSta` runs the dialog on the current thread when it is STA and on a new STA thread otherwise. `Program.Crash` uses it and then ends the process with exit code 1.
- `ShellForm` restores the shell page whatever the adapter. The INLINE 7 inner page still waits for the adapter match. The unused `Inline7Control.AdapterPrefsMatched` property goes.
- `SaveJobCustomer` returns early without a write when the trimmed customer equals what is on disk.
- Lockstep version bump (4 spots) to v1.2.38.

## Tests
- `KB load resilience`: SPN lookup finds a body-only note, ranks the code above it, honours `max`, and `SpnText` includes the note body.
- `crash log (TB1d)`: `RunOnSta` from an MTA thread runs on STA and passes an exception back.
- `data safety`: `.txt` has an associated app; an unknown extension and no extension do not (Windows CI).
- `persist startup (no wipe)`: the same customer twice leaves no `.bak`; a changed customer still writes one. Source check that the shell page restore no longer reads `AdapterPrefsMatched`.
- No new SelfTest case, so `ExpectedCaseCount` stays 52.

## Non-goals
- No IntelliDealer change (removed on beta). No J1939, updater, `.github/` or UI layout change.
- `Hit.Score` is still written by Search and SPN lookups alike; it is only read to sort within one call on the UI thread.
