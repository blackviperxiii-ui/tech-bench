# Tech Bench v1.2.22: IdGateway refuse 307/308 after non-GET

## Problem
`RealSend` followed every redirect by forcing `method = GET` and clearing body/filePath. A 307/308 on log-on / sign-off / multimedia POST could still land a later 200 for a request that never resent its payload.

## Fix
- `RedirectFollowError`: 307/308 on non-GET/HEAD returns a clear error; RealSend stops.
- 301/302/303 may still switch to GET (browser convention).
- SelfTest: policy asserts + loopback POST that receives 307 and must not follow.

## Non-goals
- No replay of POST bodies on 307/308 (refuse only).
- No clear-code / J1939 / updater changes.
